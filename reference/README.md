# reference/

Frozen lookups. **Not captured, not derived** — one-time extracts from sources
that keep their own history, committed so a question stays answerable without
a network call and without a capture budget.

Nothing here is on a cron. A file is regenerated by hand, under a new dated
name, and the old one is never edited.

## drugsfda-attrition-2026-09-03.csv

Pulled 2026-09-03 from openFDA `/drug/drugsfda.json`, matching the 70 drugs in
shortage that day to approved applications by active ingredient (57 resolved).

| column | meaning |
| --- | --- |
| `shortage_generic` | the drug as FDA's shortage feed names it |
| `active_ingredient` | dosage-form words stripped, used as the Drugs@FDA key |
| `applications` | approved applications naming that ingredient |
| `products_discontinued` | products under them with `marketing_status: Discontinued` |
| `products_marketed` | products still `Prescription` or `Over-the-counter` |

Answers **Q13** — 51% of every product ever approved for these drugs is
discontinued — and it answers it permanently, because Drugs@FDA retains
discontinued applications.

It cannot answer **Q14**. There is no date on a discontinuation anywhere in
Drugs@FDA: not in the API, and not in FDA's own bulk `MarketingStatus.txt`,
which is `MarketingStatusID | ApplNo | ProductNo` and nothing else. This file
is a snapshot of a level; Q14 needs the transitions, and only capture produces
those.

**Caveats.** Matched on ingredient name, so 13 of 70 drugs did not resolve.
Drugs@FDA counts *products* (a strength and form), not firms — so this
measures market exits, not distinct companies.
